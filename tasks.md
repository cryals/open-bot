# Open Bot — план новых модулей

**30 октября 2026 года.** Все незакрытые пункты ниже — будущая функциональность.

Предыдущая работа завершена и отправлена в GitHub: [e453dd3](https://github.com/cryals/open-bot/commit/e453dd324cebe71e30b617be07196f636e2681bd). Ticket, Metrics, Game Server Status, Watchdog и отдельная вики MkDocs уже существуют; повторно создавать их не требуется. [Отчёт выпуска](docs/RELEASE-1.0.md).

План включает **14 новых функциональных модулей**, дополнения текущего Core и **шесть адаптеров подписок**. Команды — slash, сообщения — Components V2, шаблоны — через существующий конструктор. Названия будущих команд предварительные. Тексты правил сообщества сохраняются.

## Источники и способ чтения

Материалы используются как функциональные референсы. Тексты, оформление и платные квоты других ботов не копируются.

Dyno при прямом открытии возвращал Cloudflare 403 либо пустую оболочку. Для него прочитаны доступные индексированные тексты официальных страниц; возраст отдельных снимков различается. Carl-bot загружает Markdown: прочитаны соответствующие `.md` на том же домене. JuniperBot и ProBot доступны напрямую. Наличие функции у другого бота не доказывает доступность аналогичного API для Open Bot.

Автоматические санкции и сканирование по умолчанию выключены: администратор включает правила и область их действия. Новые возможности не считаются готовыми только по наличию этого плана.

## 0. Расширения Core

Дополнить существующий Core и общие сервисы; отдельных Gateway-сессий и новой распределённой платформы не создавать.

- [ ] **CORE-01.** Добавить декларации нужных intents/событий/прав у модуля и отображение недостающих возможностей в панели; смена intents явно требует перезапуска Bot.
- [ ] **CORE-02.** Добавить capabilities чтения/управления для модерации, ролей, форм, розыгрышей, подписок и backup. Ticket-роли не получают их автоматически.
- [ ] **CORE-03.** Расширить сохраняемые задания для сроков наказаний, розыгрышей, подписок и копий: due time, lease, владелец, результат, отмена и восстановление. Не дублировать таймеры Web/Bot.
- [ ] **CORE-04.** Добавить доменные события с ID исходной операции: Moderation создаёт дело, ModLog доставляет карточку, Metrics считает результат. Запрос и выполненное действие имеют разные состояния.
- [ ] **CORE-05.** Расширить существующие templates/blocks/preview типизированными переменными и действиями модулей; сохранить лимиты V2, nonce, версии и message IDs.
- [ ] **CORE-06.** Добавить общий механизм смены ролей с разрешённым набором, иерархией и исключением managed/опасных ролей из публичной выдачи.
- [ ] **CORE-07.** Упорядочить обработку сообщения: санкции/удаление раньше автоответов и Starboard. Несколько фильтров одного события не создают одинаковые наказания.
- [ ] **CORE-08.** Использовать Redis TTL для счётчиков/cooldown с ограниченным fallback. Дела, настройки, победители, ID и подтверждения фиксировать сразу в SQLite; права не кешировать.
- [ ] **CORE-09.** Подключить модули к activity/error/metrics. Labels ограничить именами операций и исходами; хранить только нужный фрагмент нарушения с заданным сроком, без бессрочного архива всего чата.

## 1. Moderation — ручная модерация

**ID:** `moderation`. **Веб:** участники, дела, активные ограничения. **Команды:** `/warn`, `/warnings`, `/kick`, `/ban`, `/unban`, `/timeout`, `/untimeout`, `/case`, `/note`, `/purge`, `/lock`, `/unlock`.

- [ ] **MOD-01.** Создать дела с номером, типом, участником, исполнителем, причиной, временем, сроком, источником и результатом; ручные и автоматические действия используют один service.
- [ ] **MOD-02.** Реализовать warn, kick, ban, tempban, softban и снятие санкций; удаление истории при бане задаётся явно.
- [ ] **MOD-03.** Реализовать нативный timeout в пределах API. Бессрочный role-mute добавить отдельным режимом с сохранением изменяемых ролей/прав.
- [ ] **MOD-04.** Добавить список/отмену/очистку предупреждений и пороговую эскалацию. Устное сообщение AutoMod не становится warn без явной настройки.
- [ ] **MOD-05.** Добавить закрытые заметки, изменение причины/срока и историю дела; отмена не уничтожает исходную запись.
- [ ] **MOD-06.** Ограничить действия серверными полномочиями исполнителя/бота, иерархией и защищёнными ролями; запретить недопустимые цели независимо от UI.
- [ ] **MOD-07.** Сохранять задания снятия временных санкций; старое задание не снимает более позднее наказание другого модератора. Потерянный ответ сверять до повтора.
- [ ] **MOD-08.** Добавить необязательное ЛС с причиной, сроком и апелляцией. Закрытые ЛС не отменяют санкцию и не создают повторное дело.
- [ ] **MOD-09.** Реализовать purge по автору/содержимому/типу/количеству, сохранение закреплённых по умолчанию и подтверждение массового удаления с учётом bulk-delete ограничений.
- [ ] **MOD-10.** Реализовать lock/unlock выбранных каналов с исходными overwrites; восстановление не затирает последующие ручные правки администрации.

## 2. Moderation Logs — наказания в канал X

**ID:** `moderation-logs`. **Зависит от:** Moderation. **Веб:** канал, шаблоны, фильтры действий и очередь. `LOG_ID`/`LOG_WEBHOOK` остаются каналами ошибок.

- [ ] **MLOG-01.** Добавить канал X и V2-шаблоны warn/kick/ban, timeout, снятия санкции и изменения дела; сохранять ID карточки.
- [ ] **MLOG-02.** Выводить **кого / когда / кто / почему / насколько**, номер дела и фактический результат. Для kick/warn без срока — «не применяется», для постоянного ban — «бессрочно».
- [ ] **MLOG-03.** Показывать Open Bot и правило для автоматической санкции; неизвестного исполнителя не подменять человеком. Mentions по умолчанию не пингуют.
- [ ] **MLOG-04.** Сохранять доставку отдельно от исполнения: сбой канала не повторяет наказание; карточка остаётся в очереди, ошибка уходит ErrorReporter.
- [ ] **MLOG-05.** При изменении дела обновлять карточку, сохранять историю; удалённую карточку восстанавливать без второго дела.
- [ ] **MLOG-06.** Добавить ручные Discord ban/kick/timeout через Gateway/Audit Log, с корреляцией и дедупликацией собственных действий. Недоступные actor/reason отмечать неизвестными; обычный выход не считать kick.

```text
Блокировка · Дело #42
Кого: @участник · ID
Когда: дата и время
Кто: @модератор · ID
Почему: указанная причина
Насколько: 7 дней · до даты / бессрочно / не применяется
Результат: выполнено
```

## 3. AutoMod — фильтры сообщений

**ID:** `automod`. **Зависит от:** Moderation/ModLog. **Веб:** правила, приоритеты, исключения, срабатывания. **Команды:** `/automod status`, `/automod rule`, `/automod enable`, `/automod disable`.

- [ ] **AM-01.** Создать правила с фильтром, порогом/окном, приоритетом, ролями/каналами действия, исключениями, санкцией, ответом и каналом событий.
- [ ] **AM-02.** Добавить слова/фразы целиком и подстрокой, ссылки/домены с allowlist/blocklist, инвайты, скрытые ссылки и источник phishing-доменов с датой обновления.
- [ ] **AM-03.** Добавить частоту/дубли сообщений, повторы символов/слов, caps с минимальной длиной, упоминания, emoji, вложения и стикеры, включая временные окна.
- [ ] **AM-04.** Добавить длину/переносы, spoilers, Zalgo, типы файлов, media-only/YouTube-only каналы и явно включаемые honeypot-каналы.
- [ ] **AM-05.** Реализовать уведомление, удаление, warn/timeout/kick/ban, эскалацию нарушений и передачу спорного случая модератору с подтверждаемыми V2-кнопками.
- [ ] **AM-06.** Для подходящих правил использовать Discord Native AutoMod, для остальных — бот. Сохранять native rule ID; native execution и Gateway не создают двойную санкцию.
- [ ] **AM-07.** Добавить режим наблюдения, объяснение решения, минимальное доказательство с ограниченным хранением и отмену решения уполномоченным модератором.
- [ ] **AM-08.** Обрабатывать правки; исключить циклы на ботах/вебхуках и повтор за одну редакцию. Сбой phishing-источника не делает все ссылки запрещёнными.

- [ ] **RAID-02.** Добавить уведомление, карантинную роль, timeout/kick/ban, исключения и явное включение автоматических действий.

## 12. Social Feeds — подписки

**ID:** `subscriptions`. **Веб:** провайдеры, каналы, шаблоны, очередь. **Команды:** `/feed add`, `/feed list`, `/feed pause`, `/feed remove`.

Общая доставка принадлежит одному модулю; шесть провайдеров имеют отдельные адаптеры и состояния. Сбой одного источника не останавливает остальные.

- [ ] **FEED-01.** Сохранять provider/source/content IDs, получателей, message IDs и позицию чтения; канонизировать URLs/handles на сервере.
- [ ] **FEED-02.** Объединять одинаковые источники в один опрос/подписку; добавить provider rate limits, timeout, backoff и freshness.
- [ ] **FEED-03.** Дедуплицировать по content/event ID и каналу. Первое подключение начинает с текущей точки; исторический backfill включается отдельно и ограниченно.
- [ ] **FEED-04.** Добавить V2-шаблоны переменных/изображений/ссылок, фильтры и mentions. По умолчанию отправляет Open Bot, сторонние webhooks не обязательны.
- [ ] **FEED-05.** Сохранять доставку при сбоях Discord, различать получение события и отправку; неопределённый ответ не порождает бесконечные анонсы.
- [ ] **FEED-06.** Реализовать серверные credentials/OAuth, refresh/revoke и redaction; callback защищать подлинностью, дедупликацией и сроком допустимого повторения.

### Шесть адаптеров

- [ ] **FEED-YT.** YouTube: ID/handle/URL канала, новые видео, Shorts и начало эфира, переключатели типов, canonical video ID и восстановление позиции/подписки.
- [ ] **FEED-TWITCH.** Twitch: EventSub online/offline, streamer/game/title/preview, одна карточка на stream ID и её обновление после завершения; reconnect без повторного анонса.
- [ ] **FEED-KICK.** Kick: начало эфира через доступный официальный API, заголовок, категория, ссылка, preview, стабильный event ID и состояние доступа.
- [ ] **FEED-TIKTOK.** TikTok: новые видео, подпись с/без hashtags и preview через авторизованное подключение creator к Display API либо явно согласованный внешний источник. Без доступа отображать недоступность, не имитировать поддержку произвольного username.
- [ ] **FEED-REDDIT.** Reddit: новые посты subreddit, flair-фильтр, текст/изображения/ссылка и post ID. NSFW по умолчанию исключать; разрешать только явно в соответствующий возрастной канал.
- [ ] **FEED-VK.** VK: доступные сообщества, новые wall posts, keywords/attachment filters, ссылка/медиа; закрытый или удалённый источник имеет явное состояние ошибки доступа.

Доступность scopes, типов событий и квот определяется платформой. Особенно TikTok: официальный API требует одобрения приложения и авторизации creator. Страница Dyno не является доказательством доступа Open Bot к любому публичному аккаунту.

## 14. Guild Backup — ежедневный снимок сервера

**ID:** `guild-backup`. **Веб:** расписание, три копии, состав, скачивание, восстановление. **Команды:** `/backup create`, `/backup list`, `/backup restore`, `/backup status`. Требуется отдельное полномочие backup.

Это снимок Discord guild. Текущий `npm run backup` сохраняет базу/файлы Open Bot; оба вида копий нужны для разных объектов.

### Сохранение

- [ ] **BACKUP-01.** Добавить ежедневное расписание с явными временем/часовым поясом и последним успешным выполнением; после простоя не создавать серию устаревших снимков.
- [ ] **BACKUP-02.** Хранить **последние три успешные копии**. Новую фиксировать из временного места атомарно; ротацию выполнять после завершения. Сбой новой не удаляет предыдущую рабочую.
- [ ] **BACKUP-03.** Сохранять доступные guild settings, название/описание, icon/banner/splash, system/AFK/community/verification settings; перечислять недоступные поля.
- [ ] **BACKUP-04.** Сохранять роли, permissions bitfields, цвета/иконки/порядок, упоминаемость и доступные назначения участникам. Managed-роли отмечать отдельно; загрузка состава требует разрешённого intent/API.
- [ ] **BACKUP-05.** Сохранять категории/каналы: тип, имя, порядок, parent, topic, NSFW, slowmode, role/member overwrites, forum tags/defaults, voice limits/bitrate и доступные thread settings/members.
- [ ] **BACKUP-06.** Включать доступные активные/архивные ветки и forum posts. Для каждого текстового канала/ветки сохранять **последние 20 сообщений**: текст, автора/username, даты, replies, embeds/components, вложения, закрепления и доступные реакции.
- [ ] **BACKUP-07.** Копировать байты вложений/ресурсов с именами, размерами и checksum. Ограничить параллелизм, место и размер загрузки; несохранённые объекты перечислять в составе.
- [ ] **BACKUP-08.** Включать доступные emoji/stickers, bans/причины, native AutoMod, onboarding/welcome и scheduled events. Integrations/webhooks сохранять как несекретные метаданные, без токенов.
- [ ] **BACKUP-09.** Создать версионированный manifest: guild ID, время, объекты, checksum, полнота и ошибки разделов; частичный снимок явно отличать от полного.
- [ ] **BACKUP-10.** Защитить архив при хранении/скачивании, ограничить доступ capability backup и удалять ротируемые файлы. Частные данные не становятся публичными; срок копий учитывается отдельно от Ticket retention.

### Восстановление

- [ ] **RESTORE-01.** Добавить мастер выбора копии/guild/разделов, список создаваемых объектов/конфликтов/ограничений и подтверждение конкретного плана исполнителем.
- [ ] **RESTORE-02.** По умолчанию восстанавливать добавлением без удаления текущих объектов; замену выделить в отдельный подтверждаемый режим.
- [ ] **RESTORE-03.** Создавать роли → категории → каналы → ветки, сохранять mapping старых ID на новые; продолжение не создаёт второй комплект.
- [ ] **RESTORE-04.** Возвращать свойства/порядок/overwrites с remap. Приватные каналы держать закрытыми до настройки; невосстановимые permissions не заменять публичным доступом.
- [ ] **RESTORE-05.** Отправлять сообщения **от Open Bot**, от старых к новым, с вложениями и представимым V2-содержимым. В конце каждого — `-# Автор: <@ID> (username)` из снимка. Пинги отключить.
- [ ] **RESTORE-06.** Перепривязывать replies/внутренние ссылки по mapping; отсутствующие объекты пояснять. Длинные записи делить с сохранением подписи автора.
- [ ] **RESTORE-07.** Для managed-ролей, интеграций, недоступных участников и неподдерживаемых свойств показывать точный пропуск/ручное действие. Не обещать исходные snowflake ID, автора или дату отправки.
- [ ] **RESTORE-08.** Сохранять прогресс, ошибки и итог по объектам, добавить продолжение/отмену без автоматического удаления восстановленного. Rate limit переводит работу в ожидание.
- [ ] **RESTORE-09.** Ограничить схему/пути/размер распаковки входящего архива; запретить path traversal, исполнение содержимого и импорт credentials/прав входа Open Bot.

```text
Привет
-# Автор: <@18474737283> (cryals)
```

Фактический отправитель восстановленной записи — бот. Исторический автор указан подписью. Старые IDs, timestamps, чужие реакции, integration-роли и отдельные свойства Discord нельзя произвольно назначить заново: manifest и мастер явно показывают эти ограничения.

## Результат каждого модуля

В состав модуля входят серверная конфигурация с версиями, live-права, веб-раздел, slash-справка, V2-шаблоны отправляемых сообщений, устойчивое состояние операций и интеграция activity/error/metrics. Метрики содержат операции, исходы, задержки и очереди без ID пользователей в labels. Пользовательское описание добавляется в отдельную MkDocs-вики; веб-панель остаётся интерфейсом управления.
