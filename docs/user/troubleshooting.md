# Решение проблем

| Симптом                      | Что сделать                                                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| После входа нет доступа      | Убедитесь, что входите нужным аккаунтом и у вас есть роль панели на сервере `GUILD_ID`. После смены роли войдите заново. |
| OAuth сообщает о callback    | Сравните `REDIRECT` с OAuth2 → Redirects: протокол, имя хоста, порт и путь должны совпадать.                             |
| «Опубликовать» недоступно    | Сохраните черновик, выберите канал в настройках, исправьте ошибки компонентов.                                           |
| Изменения не видны в Discord | Сохранение меняет только черновик. Для правил и информации нужна публикация; для объявления — отправка или обновление.   |
| Конфликт версии              | Скопируйте свои правки, обновите страницу и перенесите их в свежую версию.                                               |
| Сообщение слишком большое    | Разделите содержимое на страницы или сообщения, сократите блоки и вложения. Вложенные компоненты тоже учитываются.       |
| Редактор пишет Not Found     | Обновите сборку и сервер вместе, перезагрузите страницу. Проверьте, что прокси направляет `/api` на нужный backend.      |
| Журнал не появился сразу     | Дайте очереди время обработать пакет; если Bot остановлен, запустите службу.                                             |
| Redis недоступен             | Локальная очередь продолжит пакетную запись. Проверьте место на диске; не удаляйте outbox.                               |
| Бот переподключается         | Проверьте сеть и статус Discord; затем локальные логи и отчёты. Перезапуск уже выполняет supervisor.                     |
| Docker Engine не работает    | Для запуска используйте Node.js. Виртуализация не требуется для `npm start`.                                             |

## Что приложить к сообщению о проблеме

Укажите версию/коммит, время с часовым поясом, последовательность действий, ожидаемый и фактический результат, ID ошибки. Скриншот обрежьте до нужного участка. Не прикладывайте `.env`, cookie или URL вебхука.

## Проверка владельцем установки

`GET /api/health` возвращает `200` при готовности Discord и `503` при его недоступности. Это не проверка всех модулей и не замена `/status`. Раздел **Настройки** показывает сервер, канал и ссылку на сохранённое сообщение.

Для восстановления из копии используйте [инструкцию](../OPERATIONS.md). Перед ручными исправлениями базы остановите процессы и сохраните текущие данные.
