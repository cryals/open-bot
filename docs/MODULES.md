# Модули, команды и восстановление

## Процессы

`npm start` запускает Core supervisor. Он применяет миграции и создаёт два независимых процесса:

- **Bot**: Gateway Discord, Core, Help, Info и будущие модули команд. Только этот процесс получает события Gateway и доставляет обычный журнал действий из SQLite.
- **Web**: Fastify, OAuth и веб-панель. Он использует общий REST-транспорт, не создавая второй Gateway-сессии. При переподключении Gateway панель может продолжать работать, пока доступен REST Discord для проверки прав.

Супервизор получает heartbeat каждые 5 секунд. Если ответов нет 30 секунд, процесс завершается и запускается заново. На первоначальный запуск отводится 60 секунд. Если Bot после запуска остаётся без подключения 120 секунд, супервизор перезапускает его. Повторные сбои увеличивают паузу от 1 до 60 секунд с небольшим случайным смещением; после минуты стабильной работы счётчик сбрасывается. Память V8 каждого рабочего процесса ограничена 384 МБ; это не ограничение всей RSS процесса.

Сбой Web не останавливает Bot. Ошибка обработчика команды получает отдельный отчёт и ответ с ID ошибки. Необработанная ошибка завершает повреждённый рабочий процесс; его восстанавливает супервизор. Потеряв связь с родителем, рабочий процесс завершает работу, чтобы не оставлять вторую копию бота. Файл supervisor.lock предотвращает одновременный запуск двух супервизоров с одной базой.

В production устанавливайте внешний менеджер службы: пример systemd в `docs/open-bot.service` перезапускает и сам супервизор. Смерть ОС, остановка внешнего менеджера, повреждение диска или недоступность Discord не могут быть устранены внутрипроцессным обработчиком. Сохранность обеспечивается постоянным каталогом data и резервными копиями; абсолютная доступность не гарантируется.

## Команды

| Команда                | Модуль | Назначение                                                                                    |
| ---------------------- | ------ | --------------------------------------------------------------------------------------------- |
| `/help [module]`       | Help   | Справка по доступным командам, сгруппированная по модулям; длинная справка листается кнопками |
| `/ping`                | Core   | Pong, время подтверждения взаимодействия Discord, Gateway ping и время работы процесса        |
| `/status`              | Core   | Административная диагностика модулей, процессов, памяти и перезапусков                        |
| `/info`                | Info   | Личное меню опубликованных правил Discord и игры                                              |
| `/send-info [channel]` | Info   | Административная отправка/обновление опубликованного информационного сообщения                |

Команды автоматически регистрируются в сервере из GUILD_ID. Новые модули попадают в справку из того же реестра. При сбое регистрации Bot продолжает обслуживать существующие кнопки, а регистрация повторяется раз в минуту. Неудачно запущенные необязательные модули также повторяют инициализацию раз в минуту.

Ответы команд личные, Components V2. Публичное сообщение создаёт только `/send-info`. До первой публикации в веб-панели команда объясняет, что нужно сначала опубликовать правила. Она не публикует текущий черновик: используется последний опубликованный снимок. При выборе другого канала он становится новым каналом публикации, а бот пытается удалить прежнее информационное сообщение. ID сохраняется в существующей базе.

Административные команды имеют default permissions Administrator и дополнительно проверяют доступ на сервере приложения: владелец сервера или настроенная роль, а без настроенной роли — Administrator. Для выбранной роли без права Administrator доступ к командам можно отдельно разрешить в настройках интеграции Discord. Одних клиентских default permissions недостаточно для авторизации, поэтому серверная проверка остаётся обязательной.

Публикация из Web и Info использует один Publisher и общую SQLite-блокировку. Сохранение правил/настроек проверяет блокировку внутри транзакции. Блокировка протухает через 90 секунд после аварии, сетевой бюджет публикации — 30 секунд. Незавершённые попытки сохраняют nonce: повтор создания использует Discord enforce_nonce в пределах окна дедупликации Discord. Это снижает риск дубликатов при потере ответа, но не является гарантией exactly once при длительном разрыве связи.

## Новый модуль

1. Создайте `src/server/modules/<id>/index.ts` с default export типа BotModule.
2. Укажите уникальные id, title, description и зависимости. Опишите команды и их обработчики в commands; для административных команд выставляйте admin и default permissions.
3. Добавьте один загрузчик в `src/server/modules/catalog.ts`.
4. Соберите и перезапустите приложение. Реестр зарегистрирует команды, а Help покажет справку автоматически.

```ts
import { SlashCommandBuilder } from 'discord.js';
import type { BotModule } from '../../runtime/types.js';
import { notice } from '../../render.js';

const module: BotModule = {
  id: 'example',
  title: 'Example',
  description: 'Пример подключаемого модуля.',
  dependencies: ['core'],
  commands: [
    {
      data: new SlashCommandBuilder().setName('example').setDescription('Пример команды'),
      async execute({ interaction, signal }) {
        signal.throwIfAborted();
        await interaction.editReply(notice('Модуль подключён.'));
      },
    },
  ],
};
export default module;
```

Start/stop входят в общий ModuleLifecycle. Модуль снимает собственные подписки и таймеры в stop. Start получает AbortSignal; инициализация Core ограничена 25 секундами, остальных модулей — 10 секундами, stop — 5 секундами. Обработчики команд получают AbortSignal и ограничены 45 секундами. Собственное I/O должно учитывать этот сигнал; синхронную тяжёлую работу следует выносить из Gateway-процесса. Изолированный процесс Web реализует тот же lifecycle, используя собственный контекст.

## Ошибки

В `.env` добавлены:

```dotenv
LOG_ID=123456789012345678
LOG_WEBHOOK=https://discord.com/api/webhooks/ID/TOKEN
```

Оба значения необязательны. LOG_ID — отдельный канал ошибок; он не заменяет канал обычного журнала, выбранный в веб-панели. LOG_WEBHOOK — резервный транспорт, доступный супервизору независимо от Gateway. Вебхук берётся из текстового канала Discord. Для канала ошибок боту нужны View Channel, Send Messages и Attach Files.

Каждый отчёт получает UUID, время, PID, процесс, модуль/операцию, сообщение, stack trace, цепочку cause и контекст действия (например ID пользователя, канала и взаимодействия). Секреты редактируются до записи. Содержимое HTTP-запросов, cookie, OAuth-коды и токены не собираются.

Полный отчёт сохраняется в `data/errors/errors-<date>-<process>-<pid>.jsonl`. При настроенном транспорте отдельная запись помещается в `data/errors/pending/<UUID>.json` атомарной заменой файла. Доставкой занимается только супервизор:

1. Если Bot подключён и LOG_ID настроен, используется бот.
2. Если Gateway недоступен или отправка ботом завершилась ошибкой, используется LOG_WEBHOOK.
3. Если оба способа недоступны, запись остаётся на диске. Повтор откладывается с увеличением паузы, максимум до пяти минут.

В Discord уходит тихое сообщение Components V2 без упоминаний и полный JSON во вложении. Длинный stack trace сокращается только в тексте сообщения. При получении подтверждения очередь удаляется, JSONL сохраняется. При потере подтверждения возможен повтор с тем же ID; доставка рассчитана на сохранение отчёта, а не на exactly once. Повреждённый файл очереди сохраняется с расширением .corrupt и не блокирует остальные отчёты. Ошибки самой доставки пишутся локально, не создавая рекурсивную очередь.

Журнал действий остаётся в SQLite и `data/logs/<date>-<pid>.jsonl`; разделение файлов по PID предотвращает перемешивание записей разных процессов. При ошибке записи активности в SQLite сохраняется JSONL и создаётся отдельный отчёт об ошибке. `npm run backup` включает базу, uploads, logs и errors, в том числе очередь.

Основные первичные справочники: [Discord Application Commands](https://docs.discord.com/developers/interactions/application-commands), [Components](https://docs.discord.com/developers/components/reference), [Webhook](https://docs.discord.com/developers/resources/webhook), [Node.js child processes](https://nodejs.org/docs/latest-v24.x/api/child_process.html), [Node.js fatal errors](https://nodejs.org/docs/latest-v24.x/api/process.html#warning-using-uncaughtexception-correctly).
