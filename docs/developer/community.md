# Контракты модулей сообщества

## Настройки и процессы

`ApplicationSettingsStore` хранит поведение в `module_config/application`. ENV — технические секреты и начальные значения прежних флагов. Bot фиксирует реально применённые intents в `gateway-applied`; Web не создаёт Gateway. Supervisor обрабатывает запрос перезапуска Bot и переключение Metrics worker.

`CommunityStore` кеширует конфигурации обработки сообщений на секунду. Выдача ролей, свои команды и доступ к формам используют свежую конфигурацию. Актуальные роли Discord проверяются на сервере; Redis не хранит права.

Catalog содержит отдельные модули; `community-module.ts` собирает slash-оболочки. `community-runtime.ts` владеет порядком Gateway-обработки и ограниченным набором фоновых задач. Долгая копия не блокирует формы и розыгрыши. Один scope имеет не больше одного исполнителя.

Вход участника записывается `JoinPolicyService.join` синхронно в `core_jobs` до ограниченной очереди сообщений Gateway. Повтор одного joined_at не создаёт второй job; всплеск сообщений не должен отбрасывать новые входы. Сеть и санкции выполняются позже владельцем задания.

Native AutoMod передаёт обработку Discord только при совпадении сохранённой сигнатуры `[enabled, rule]` с актуальной конфигурацией. Общий `nativeTrigger` валидирует создание и серверное сохранение настроек. Периодическая сверка использует тот же scope `automod`, что ручное задание. Перед созданием список Discord сверяется по creator_id и стабильной метке правила; это восстанавливает ID после потерянного POST. Ошибка сверки сбрасывает сигнатуры делегирования, сохраняя обработку доступных сообщений ботом. Смена неизменяемого trigger_type удаляет старое правило и создаёт новое; чужие правила не изменяются.

## Сохраняемые операции

Миграции 008–011 добавляют controls/jobs/events, дела/доставку модерации, community state, заявки, розыгрыши, подписки, копии/шаги восстановления и зашифрованные credentials. Новая миграция — новый файл.

`JobStore` сохраняет due time, lease, владельца, попытки и результат. Исполняет только Bot; HTTP/slash фиксируют запрос. Lease не делает повтор удалённого действия безопасным: reconciliation принадлежит владельцу операции.

Moderation: `prepared → queued → running → applied/failed/unknown`. Подтверждение связано с автором и сроком. После остановки во время REST действие становится `unknown`. Старое истечение не снимает новое наказание; бан дополнительно сверяет текущую причину Discord.

Доменное событие создаётся после изменения дела. ModLog хранит доставку и message ID отдельно; сбой карточки не повторяет санкцию. Внешние действия берутся из Audit Log events, собственные коррелируются по причине дела. Обычный выход не считается kick.

## Области данных

Порядок: AutoMod → Slowmode → Autoresponder; затем Starboard заново читает исходник. Сканирование выключено по умолчанию. Фрагменты нарушений ограничены 500 символами и сроком; полный чат не копируется в постоянный audit.

Redis TTL обслуживает окна/cooldown с ограниченным локальным fallback. Дела, настройки, решения, победители, ID и шаги пишутся в SQLite сразу. Activity сохраняет disk outbox/Redis Streams с ACK после записи.

`GuildAuthority` проверяет guild, permissions, иерархию и публичные роли. Роли доступа Open Bot/Ticket/форм нельзя раздавать публично даже без опасных Discord bits. Заявитель формы не получает staff API через свой OAuth.

## Подключения

Provider URLs фиксированы; источники канонизируются. Fetch имеет timeout, запрет редиректов и предел ответа. Получение события отделено от доставки. Первый poll не становится backfill на втором. Неопределённый POST не повторяет анонс бесконечно.

Vault: AES-256-GCM, случайный IV, AAD `provider:account`. Ключ — только ENV. Refresh объединяется в процессе и сохраняется с проверкой прежней записи: старый refresh не восстанавливает удалённое подключение и не перезаписывает новый grant. API отдаёт только provider/account/time.

YouTube live search использует сохраняемый бюджет. Twitch EventSub обрабатывает welcome/keepalive/reconnect/revocation. OAuth callback связан со state, cookies, исполнителем и сроком; применяется PKCE. TikTok не имитирует доступ к произвольным username.

## Архивы и восстановление

Архив — gzip JSON с версией, manifest и файлами SHA-256. Импорт ограничивает распаковку, структуру, размер и checksum; имена пользователя не становятся путями. Сжатие/распаковка асинхронны. Credentials и права входа Open Bot не импортируются.

Каждый объект имеет сохраняемый шаг и remap. После неизвестного результата создание требует сверки. Replacement затрагивает выбранные разделы и проверяет guild канала перед удалением. Исходные объекты остаются до создания новых. При невосстановимых overwrites канал остаётся закрытым.

## Метрики

Activity различает запрос, браузерное наблюдение и завершённую операцию. OAuth/credentials не попадают в логи; label своих slash-команд нормализован в `run`.

Новые gauges: `open_bot_module_jobs{kind,state}`, `open_bot_moderation_cases{action,state}`, `open_bot_feed_delivery{state}`, `open_bot_form_submissions{state}`. Labels не содержат IDs, URLs, контент или имена пользовательских команд. Выключение Metrics останавливает snapshots; повторное включение не дублирует registry.
