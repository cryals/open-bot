# Создание и обслуживание модулей

## Контракт BotModule

Модуль команд экспортирует `BotModule` из `src/server/runtime/types.ts`. В нём описываются ID, название, зависимости, команды, обработчики кнопок и lifecycle. Единственный каталог подключения — `src/server/modules/catalog.ts`. Help и регистрация slash-команд читают этот же каталог.

```ts
import { SlashCommandBuilder } from 'discord.js';
import type { BotModule } from '../../runtime/types.js';
import { notice } from '../../render.js';

const module: BotModule = {
  id: 'example',
  title: 'Example',
  description: 'Диагностика собственного сервиса.',
  dependencies: ['core'],
  commands: [
    {
      data: new SlashCommandBuilder().setName('example').setDescription('Проверить сервис'),
      async execute({ interaction, signal }) {
        signal.throwIfAborted();
        await interaction.editReply(notice('Сервис доступен.'));
      },
    },
  ],
};
export default module;
```

Затем добавьте загрузчик с тем же ID в каталог. Пример — шаблон для нового модуля; в текущем релизе команда `/example` не зарегистрирована.

## Автоматические страницы вики

`npm run docs:generate` читает каталог Bot-модулей и метаданные Web. Для каждого модуля создаётся `docs/user/modules/ID.md`, общий список — `docs/user/catalog.md`. Название, описание, зависимости, события, права и slash-подкоманды берутся из definitions, без входа в Discord и без запуска lifecycle.

Генератор обновляет только области `module-reference:start/end`; заметки снаружи сохраняются. В `mkdocs.yml` аналогично обслуживается блок `module-reference-nav:start/end`. Новый модуль, зарегистрированный в каталоге, получает страницу и пункт меню автоматически. Пользовательские команды из рабочей SQLite в статическую вики не экспортируются.

Workflow **Documentation** запускается при изменениях исходников, скрипта, зависимостей и документации: Node.js → установка зависимостей → генерация страниц → строгая сборка MkDocs → Pages artifact → публикация `main`. Автогенерация входит в артефакт сборки, CI не делает коммит от своего имени. В репозиторий страницы добавляются обычным коммитом после локальной генерации. Учётная запись должна разрешать GitHub Actions и Pages для приватного репозитория.

## Права slash-команд

Manager заранее подтверждает команду через ephemeral `deferReply`. Обработчик отвечает `editReply`, учитывает переданный `AbortSignal` и завершает I/O в отведённое время. Для административной команды задайте **и** `admin: true`, **и** `setDefaultMemberPermissions(PermissionFlagsBits.Administrator)`. Серверная проверка обязательна независимо от настроек интеграции Discord.

Имена команд должны быть уникальны во всём каталоге. Ошибка инициализации необязательного модуля видна в `/status`; runtime выполняет повторную попытку. Не создавайте собственный бесконечный цикл повторного старта поверх этого механизма.

## Кнопки и lifecycle

У кнопок есть уникальный версионированный prefix. Проверяйте guild, структуру custom ID и владельца личной навигации. В отличие от команд, обработчик кнопки сам вызывает `deferUpdate` или `deferReply` до длительного I/O. Ошибка должна позволять пользователю открыть актуальное меню заново.

`start` создаёт нужные подписки и таймеры; `stop` снимает их и освобождает ресурсы. Cleanup должен работать и после частично неудачного старта. Не оставляйте таймеры, которые создадут вторую копию фоновой задачи при повторе инициализации.

На старте Core получает 25 секунд, прочие модули — 10; на stop — 5. Команда ограничена 45 секундами. Переданный сигнал не отменяет I/O автоматически: передайте его в используемый клиент. Синхронная тяжёлая работа блокирует весь Bot worker и heartbeat; выносите её из Gateway-процесса.

## Web и база

Web — отдельный lifecycle-модуль, а не BotModule в каталоге Gateway. Новую возможность панели подключайте через серверные маршруты и React-раздел. Повторно используйте общие проверки OAuth/CSRF, валидируйте тело через Zod и авторизуйте операцию на сервере.

Не заводите второй Gateway в Web. Для фоновых изменений из панели сохраняйте команду/состояние в базе или явно спроектируйте IPC; память двух workers не общая.

Добавляйте таблицы через новую миграцию. Долгие операции проектируйте с устойчивым состоянием, дедупликацией и понятным восстановлением после перезапуска. Повторный запуск не должен повторять уже выполненное внешнее действие.

## Диагностика и завершение

Операции логируйте через существующий ActivityService; аварии — через ErrorReporter. Не записывайте секреты в before/after или custom IDs. Метрики должны дополнять эти механизмы, а не заменять журнал: [телеметрия](telemetry.md).

Обновите `/help`, пользовательское руководство, env-пример и резервное копирование, если изменились публичные команды или данные. Проверяйте с FakeDiscord; настоящий сервер не должен получать тестовые публикации или команды питания.

Точные runtime-контракты: [MODULES.md](../MODULES.md). Навык сопровождения: [open-bot-modules](https://github.com/cryals/open-bot/blob/main/skills/open-bot-modules/SKILL.md).
