# Redis и пакетная запись журнала

Схема согласована пользователем 2026-10-30: Redis Streams, пакет до 100 событий или раз в секунду, подтверждение после SQLite, дедупликация, локальная очередь при сбое Redis, Redis в Docker Compose.

## Границы

SQLite остаётся источником правил, настроек, сессий, публикаций и ID сообщений. Эти операции выполняются сразу и сохраняют проверки доступа и оптимистические версии. Redis не кеширует авторизацию и не отменяет проверку роли Discord.

Меняется только подробный журнал активности. `record` формирует событие с UUID и сохраняет его в дисковом outbox рядом с базой. В этой операции нет запросов SQLite. Дисковая копия остаётся до завершения записи в SQLite: она позволяет восстановиться даже после потери Redis. Это дополнительная файловая запись ради сохранности; Redis не является единственным экземпляром события.

## Поток

Единственный потребитель в Bot раз в секунду или после накопления 100 локальных событий отправляет пакет в Redis Stream. Группа `sqlite` с постоянным именем потребителя сначала читает неподтверждённые сообщения, затем новые. SQLite получает подготовленные INSERT в одной транзакции, с UNIQUE по UUID. JSONL дописывается пакетом; затем удаляются локальные копии, выполняются XACK и XDEL. Повтор после аварии безопасен для SQLite; JSONL может содержать повторные UUID при аварии между записью файла и подтверждением.

Web и Bot используют общий outbox в постоянном каталоге данных. Web не запускает второго потребителя. Без REDIS_URL, либо при недоступном Redis, Bot обрабатывает дисковую очередь такими же пакетами напрямую. Недоступность Redis не останавливает сохранение правил и не приводит к бесконечному росту очереди, пока SQLite исправна. Ошибка Redis видна в журнале состояния и редактируется перед error-логированием.

SQLite и JSONL подтверждаются до удаления outbox. При ошибке SQLite или JSONL файл остаётся для повтора. Повреждённая запись сохраняется отдельно и не блокирует остальные. Закрытие сервиса останавливает таймер и заканчивает текущий пакет до закрытия базы; оставшиеся файлы подхватятся после перезапуска.

## Смежные дефекты журнала

Экспорт читает журнал страницами, освобождая SQLite statements перед передачей очередной порции клиенту. Ошибка доставки в один Discord-канал не блокирует другие каналы: отдельная задержка повтора на канал.

## Развёртывание и проверка

REDIS_URL задаётся для обычной установки. Compose добавляет внутренний Redis с AOF, healthcheck и постоянным томом без публикации порта хоста. Готовность бота не зависит от готовности Redis: есть локальный пакетный режим. Копии включают activity-outbox; восстановление SQLite/outbox достаточно для возврата неподтверждённых событий без восстановления Redis.

Проверки: штатный пакет, повторы UUID, перезапуск с outbox, недоступный Redis, pending после сбоя consumer, экспорт одновременно с сохранением, два канала доставки. Действия Discord выполняются только через FakeDiscord. Проверка с настоящим Redis отдельно помечается как интеграционная; отсутствие Docker Engine не считается успешной проверкой Redis.
