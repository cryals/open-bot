# Open Bot: настройка и эксплуатация

[README на русском](../README_RU.md) · [English README](../README.md) · [Модули](MODULES.md)

Для запуска в контейнерах используйте [инструкцию Docker Compose](DOCKER.md): готовую сборку, постоянный том, резервное копирование и дополнительный Caddy для HTTPS. Ниже описаны также настройки обычной установки Node.js.

## Окружение

Требуется Node.js 24.18 или новее. Установка запускается из корня проекта: там находятся `rules/`, `migrations/` и собранный `dist/`.

Загрузчик читает `.env` из корня проекта и родительской папки. Локальный файл имеет приоритет; уже заданные переменные процесса не перезаписываются. `.env`, база, сессии, вложения и журналы исключены из Git.

| Переменная      | Назначение                                                                     | Значение по умолчанию    |
| --------------- | ------------------------------------------------------------------------------ | ------------------------ |
| `BOT_TOKEN`     | Токен аккаунта бота.                                                           | Обязательна.             |
| `GUILD_ID`      | Единственный Discord-сервер этой установки.                                    | Обязательна.             |
| `CLIENT_ID`     | ID приложения Discord.                                                         | Обязательна.             |
| `CLIENT_SECRET` | Секрет OAuth-приложения.                                                       | Обязательна.             |
| `REDIRECT`      | Полный OAuth callback, например `http://localhost:3000/auth/discord/callback`. | Обязательна.             |
| `PORT`          | Порт HTTP-сервера.                                                             | `3000`                   |
| `HOST`          | Адрес прослушивания.                                                           | `127.0.0.1`              |
| `DATABASE_PATH` | Путь к базе SQLite.                                                            | `./data/open-bot.sqlite` |
| `ADMIN_ROLE_ID` | Начальная административная роль при создании базы.                             | Пусто.                   |
| `TRUST_PROXY`   | Доверять прокси, который заменяет `X-Forwarded-*`.                             | `false`                  |
| `APP_ORIGIN`    | Origin интерфейса; для Vite — `http://localhost:5173`.                         | Origin из `REDIRECT`.    |
| `LOG_ID`        | Канал подробных отчётов об ошибках.                                            | Отключён.                |
| `LOG_WEBHOOK`   | Резервный Discord-вебхук ошибок.                                               | Отключён.                |

`APP_ORIGIN` и `REDIRECT` должны иметь одинаковые hostname и протокол; порт может отличаться. Канал обычного журнала действий выбирается в панели независимо от `LOG_ID`.

## Подключение Discord

1. Создайте приложение и бота в [Developer Portal](https://discord.com/developers/applications).
2. Добавьте точный `REDIRECT` в **OAuth2 → Redirects**.
3. Установите приложение на сервер со scopes `bot` и `applications.commands`.
4. В каналах публикации выдайте **View Channel**, **Send Messages**, **Read Message History** и **Attach Files**. Для журнала и ошибок также нужен доступ к соответствующим каналам.
5. Заполните `.env`, выполните `npm ci`, `npm run build`, затем `npm start`.

Используется только intent `Guilds`. Привилегированные `Message Content` и `Server Members` не нужны. Команды регистрируются в `GUILD_ID` автоматически при запуске модулей.

## Вход и права

Веб-вход использует OAuth scope `identify`. OAuth-токен нужен для получения профиля и не сохраняется. Каждый привилегированный запрос проверяет актуальные роли через REST API бота.

- Пока роль не настроена, доступны владелец сервера и участники с правом **Administrator**.
- После выбора роли доступны её участники и владелец сервера.
- Владелец сохраняет доступ для исправления настроек.
- `ADMIN_ROLE_ID` задаёт начальную роль при создании базы; далее используйте панель.

Сессия хранится на сервере и действует восемь часов. Cookie использует `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS. Изменения требуют CSRF-токен и допустимый Origin. Недоступность Discord не отключает проверку прав.

## Правила и публикации

`rules/game.md` и `rules/discord.md` импортируются при создании базы. Правки этих файлов после первого запуска не заменяют сохранённые тексты. Дальнейшее редактирование выполняется в панели.

Сохранение меняет черновик. Публикация создаёт снимок, сохраняет канал и ID сообщения и обновляет активную версию. Возврат старой версии в черновик ничего не публикует. Конфликт версий при одновременном редактировании защищает от молчаливой перезаписи.

Вступление остаётся на каждой странице правил. Длинный текст разбивается общим алгоритмом в панели и боте без обрезания содержания. Перед отправкой проверяются схема, число компонентов и безопасный размер сообщения. Упоминания в правилах не создают пинги.

`/send-info` использует последний опубликованный снимок. Первую публикацию выполните в панели. Публикации используют общий сохраняемый lock; при ошибке отправки предыдущий активный снимок остаётся доступен. Удалённое сообщение восстанавливается следующей публикацией. При переносе в другой канал бот после успешной отправки пытается убрать прежнее сообщение.

## Редактор, сообщения и вложения

«Информация» редактирует публичное сообщение целиком: текст, контейнеры, изображения, файлы, разделители и кнопки. В строке действий можно добавить ссылку на вики, лаунчер или поддержку, а также встроенную кнопку «Читать правила».

«Сообщения бота» поддерживает до десяти сообщений в одной отправке, черновики, шаблоны и редактирование по сохранённому ID. Повтор прерванной отправки без изменения содержимого продолжает её с сохранённого места. Тихая отправка и типы упоминаний задаются отдельно; редактирование не отменяет уже полученные уведомления.

Импорт и экспорт JSON используют формат Open Bot, а не универсальный формат сторонних конструкторов. Для переноса в другую установку перенесите также вложения либо загрузите их заново.

Лимиты загрузки: 8 МБ на файл, 8 МБ суммарно и до десяти файлов на сообщение. Поддерживаются PNG, JPEG, GIF, WebP, PDF, TXT, MD, CSV, JSON, ZIP и DOCX; изображения проверяются по содержимому. Файлы лежат в `uploads/` рядом с базой. Предпросмотр защищён авторизацией. Discord получает настоящие вложения через `attachment://`.

## Журнал действий и отчёты об ошибках

Журнал сохраняет действия интерфейса, изменения полей, операции API, публикации, команды и действия бота. Есть значения до/после и построчная разница. Изменения текста объединяются с задержкой около 900 мс; наблюдения браузера помечаются `ui.*` отдельно от серверных событий. Обычные сообщения участников не отслеживаются.

Полные записи хранятся в SQLite и ежедневных JSONL рядом с базой. В панели есть поиск, просмотр и экспорт. После выбора канала журнала новые события поступают в очередь Discord; уже поставленные события сохраняют первоначальный канал. В Discord длинный diff сокращается, а полный остаётся локально. Секреты и служебные данные авторизации исключаются из журнала; само содержимое загруженных файлов в него не копируется.

Ошибки независимо записываются в `errors/` с UUID, временем, процессом, областью сбоя, сообщением, stack trace и причиной. Единственный отправитель в супервизоре читает очередь `errors/pending/`: сначала канал `LOG_ID` через бота, затем `LOG_WEBHOOK`. Для вебхука не нужна работающая Gateway-сессия бота. Если оба способа недоступны, файлы остаются в очереди до повторной попытки. При потере подтверждения возможен повтор отчёта с тем же UUID.

## Production

Запуск состоит из супервизора и отдельных процессов Bot и Web. Веб-панель обслуживается Fastify из `dist/web/`; отдельный Vite в production не требуется. Подробности перезапуска и ограничения восстановления — в [MODULES.md](MODULES.md).

На VPS:

1. Разместите проект, установите зависимости и выполните сборку.
2. Задайте `REDIRECT=https://ваш-домен/auth/discord/callback` и зарегистрируйте его в Discord.
3. Настройте HTTPS и прокси на `HOST:PORT`. `TRUST_PROXY=true` задавайте только за доверенным прокси, который заменяет входящие forwarded-заголовки.
4. Создайте отдельного пользователя службы и дайте ему запись в каталог данных.
5. Адаптируйте [open-bot.service](open-bot.service) под пути установки и включите службу.

Шаблон systemd использует `/opt/open-bot`, пользователя `open-bot`, `Restart=always` и отдельный доступ на запись к `/opt/open-bot/data`. Если меняете `DATABASE_PATH`, согласуйте его с правами службы. Включённый `compose.yaml` собирает Docker-образ из исходников и задаёт `HOST=0.0.0.0` и постоянный том данных; отдельно устанавливать systemd внутри контейнера не требуется.

`GET /api/health` возвращает `200`, когда бот готов, и `503`, когда подключение не готово. Отдельные рабочие процессы не заменяют внешний менеджер службы, резервные копии и доступный Discord.

## Резервные копии и восстановление

### Пакетный журнал и Redis

`REDIS_URL=redis://127.0.0.1:6379/0` подключает Redis 8 (поддерживается также Redis 7) для очереди активности. Для внешнего сервера используйте ACL, пароль и `rediss://`; не публикуйте Redis в интернет. `REDIS_KEY_PREFIX` по умолчанию `open-bot`; ключ также включает GUILD_ID. Две независимые установки с разными базами должны использовать разные префиксы или Redis DB.

События админки и бота сначала получают UUID и попадают в `activity-outbox/` рядом с SQLite. Процесс Bot переносит до 100 событий через Redis Streams и пишет их одной SQLite-транзакцией, раз в секунду или при накоплении 100 локальных событий. Web только создаёт записи outbox. Это уменьшает число транзакций; файловая запись каждого события сохраняется ради восстановления после аварии. Реальное ускорение зависит от диска и нагрузки.

XACK/XDEL выполняются после SQLite и пакетной записи JSONL. UNIQUE по UUID исключает повторную запись в SQLite при восстановлении consumer. В JSONL после аварийного повтора возможны одинаковые `eventId`. События направляются в канал журнала, выбранный на момент записи пакета. Неисправный старый канал имеет собственную паузу повтора и не блокирует новый.

Если Redis отключён, недоступен или отклоняет команды, те же пакеты читаются из локальной очереди напрямую. Приложение продолжает работать; ошибка видна в журнале состояния. Не удаляйте outbox при восстановлении. Переполненный или повреждённый диск не обеспечивает сохранность: проверяйте свободное место и резервные копии. `.corrupt`-файлы сохраняются для разбора отдельно и не блокируют остальные события.

Правила, настройки, сессии, публикации и ID сообщений сохраняются в SQLite сразу. Авторизация не кешируется в Redis. Видимость новых записей журнала задерживается примерно на секунду, а при большой очереди — до её обработки. При остановке выполняется последний пакет; остаток подхватывается следующим Bot.

При выключенном Bot новые события Web остаются на диске до его запуска. Очередь и история не имеют автоматического срока удаления; контролируйте занимаемый объём. `npm run backup` включает `activity-outbox/`. Для согласованной копии SQLite и очереди остановите все процессы перед копированием; онлайн-копирование меняющихся файлов не является атомарным снимком.

```sh
npm run backup
```

Скрипт использует SQLite online backup и создаёт папку `data/backups/<UTC-время>/`. В неё попадают `open-bot.sqlite`, `uploads/`, `logs/` и `errors/`, если эти каталоги существуют. SQLite копируется согласованно; файлы вложений и журналов копируются отдельными операциями. Для одной неподвижной копии всех данных сначала остановите приложение.

Восстановление:

1. Остановите службу и убедитесь, что Bot, Web и супервизор завершены.
2. Сохраните текущие данные отдельно, включая SQLite и её `-wal`/`-shm`, если они остались.
3. Восстановите базу и соседние `uploads/`, `logs/`, `errors/`, `activity-outbox/` из одной резервной копии. Не подмешивайте старые `-wal`/`-shm` к восстановленной базе. При восстановлении старого снимка используйте пустой Redis DB или новый REDIS_KEY_PREFIX, чтобы не импортировать события другой временной точки.
4. Проверьте владельца файлов, `.env` и `DATABASE_PATH`.
5. Запустите службу. Миграции применятся автоматически.

Старые одиночные `.sqlite`-копии не содержат вложений. Копии и журналы могут содержать административные тексты и персональные данные участников операций; храните их с доступом для администрации.

Перед обновлением кода остановите службу, создайте копию, обновите исходники, выполните `npm ci` и `npm run build`, затем запустите службу.

## Разработка и оформление

Задайте `APP_ORIGIN=http://localhost:5173` и выполните `npm run dev`. Открывайте интерфейс по этому origin; OAuth callback остаётся на серверном порту. Vite проксирует `/api` и `/auth`. После разработки уберите `APP_ORIGIN` или замените на production origin.

Оформление адаптировано из сайта владельца `als.stopco.ru`: монохромные поверхности, квадратные рамки, белые уголки, Unbounded / IBM Plex Mono / Inter, локальный фон и WebGL Neural Glow. Источник и ревизия — в [дизайн-документе](superpowers/specs/2026-10-30-als-theme-and-activity.md). Цвета и шрифты задаются в `src/web/theme.css`; геометрия редактора — в `style.css` и `builder.css`. Google Fonts загружает шрифты; системное уменьшение движения останавливает анимацию.

Исходники бейджей README: `scripts/readme-badges.mjs`. Пересоздание:

```sh
node scripts/readme-badges.mjs
```

Автотесты используют FakeDiscord. Существующий `tests/ui-harness.ts` предназначен для изолированной ручной проверки, production его не импортирует.
